# Лабораторна робота №7: Узагальнені типи (Generics). IRepository з where-обмеженнями та тестами.

**Тема:** Узагальнені типи (Generics). IRepository з where-обмеженнями та тестами.

**Мета:** Навчитися створювати узагальнені інтерфейси та класи, застосовувати where-обмеження для типів-параметрів, а також розробляти юніт-тести за допомогою xUnit для перевірки коректності узагальнених реалізацій.

## Хід роботи
У ході виконання роботи за допомогою .NET CLI було створено консольний проєкт lab7v4 та тестовий проєкт lab7v4.Tests (xUnit) із відповідним посиланням між ними. У проєкті реалізовано базовий інтерфейс IEntity з властивістю Id та клас сутності Category відповідно до варіанту 4. На їх основі розроблено узагальнений інтерфейс IRepository<T> із обмеженням where T : class, IEntity та його реалізацію InMemoryRepository<T> для виконання CRUD-операцій у пам'яті. Для перевірки коректності роботи написано комплект xUnit-тестів, які покривають усі методи та крайні випадки з обробкою винятків, а також продемонстровано базові операції в методі Main. Усі юніт-тести успішно пройдено за допомогою команди dotnet test.

## Відповіді на контрольні питання

* **Яка роль where-обмежень у Generics? Наведіть приклади їх використання.**  
  `where`-обмеження накладають умови на типи-параметри `T`, що дозволяє компілятору гарантувати наявність необхідних властивостей, методів або базових типів у переданих аргументах (наприклад, `where T : class` обмежує `T` посилальними типами, `where T : IEntity` гарантує наявність властивості `Id`, а `where T : new()` вимагає наявності публічного конструктора без параметрів).

* **Навіщо потрібен шаблон IRepository? Які переваги він дає?**  
  Шаблон `IRepository` відокремлює бізнес-логіку програми від деталей доступу до даних. Це дозволяє легко змінювати джерело збереження даних (наприклад, замінити збереження в пам'яті `InMemoryRepository` на базу даних SQL) без зміни коду, який використовує цей репозиторій, а також суттєво спрощує написання автоматичних тестів.

* **Поясніть, чому юніт-тести є важливими при розробці узагальнених компонентів.**  
  Оскільки узагальнений компонент призначений для роботи з багатьма різними типами даних, юніт-тести дозволяють переконатися в його коректній та універсальній поведінці в усіх граничних сценаріях (додавання дублікатів, видалення неіснуючих елементів), а також запобігають виникненню регресійних помилок під час зміни або розширення коду.

* **Які проблеми вирішують Generics порівняно з використанням object?**  
  Generics забезпечують строгу перевірку типів ще на етапі компіляції (що виключає помилки `InvalidCastException` у runtime) та значно підвищують продуктивність програми за рахунок відсутності витрат на операції упаковки та розпаковки (boxing/unboxing) при роботі зі значущими типами даних.
