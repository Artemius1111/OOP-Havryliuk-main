## 2. Відповіді на контрольні запитання

1. **Чому делегати є зручним механізмом для передавання поведінки в узагальнені методи?**
   Делегати дозволяють передавати методи та функції як параметри, розділяючи структуру перебору даних від логіки обробки конкретного елемента.

2. **У чому різниця між Func<T, TResult>, Action<T> та Predicate<T>?**
   * `Func<T, TResult>` — приймає параметр `T` та обов'язково повертає результат `TResult`.
   * `Action<T>` — приймає параметр `T` та виконує дію, не повертаючи значення (`void`).
   * `Predicate<T>` — приймає параметр `T` та повертає `bool` (використовується для перевірки умов).

3. **Які переваги дає поєднання делегат-методів і лямбда-виразів під час роботи з колекціями?**
   Забезпечує лаконічний та виразний код без необхідності створювати окремі явні методи або анонімні класи для одноразових операцій.

4. **У яких випадках власні утиліти на кшталт Map чи Filter корисно реалізувати самостійно, навіть якщо існує LINQ?**
   * У високонавантажених системах для зменшення кількості аллокацій пам'яті (без створення ітераторів та об'єктів LINQ).
   * При роботі у середовищах із обмеженнями (GameDev / Unity), де стандартний LINQ викликає небажану роботу GC (Garbage Collector).
