
# Лабораторна робота №3

### Тема 
Життєвий цикл об’єкта та керування ресурсами.
### Мета
Поглибити розуміння життєвого циклу об’єкта в C#, навчитися працювати з некерованими ресурсами, реалізувати інтерфейс `IDisposable` та патерн Dispose.
### Хід роботи
У ході роботи я створив консольний проєкт lab3v4 і реалізував клас MemoryCache із повним патерном Dispose та інтерфейсом. Також я продемонстрував три сценарії керування ресурсами (автоматичний через using, ручний виклик Dispose() та фіналізацію через GC.Collect()) у методі Main і завантажив код на GitHub.

### Контрольні запитання та відповіді

1. Життєвий цикл об'єкта - це етапи існування об'єкта від створення до видалення: виділення пам'яті в купі та виклик конструктора → використання → збирання сміття (GC) → фіналізація/виклики деструктора.

2. Керовані ресурси — це пам’ять програми, яку .NET сам очищає автоматично. Некеровані ресурси — це відкриті файли, бази даних чи мережеві з'єднання, які ви мусите закривати вручну у коді, інакше вони залишаться заблокованими.

3. Iнтерфейс IDisposable забезпечує стандартний спосіб для явного та своєчасного звільнення некерованих ресурсів через метод `Dispose()`, не чекаючи виклику GC.

4. Оператор using гарантує автоматичний виклик методу `Dispose()` після завершення блоку коду, навіть у разі виникнення помилок (винятків).

5. Повідомляє збирачу сміття (GC), що ресурси об'єкта вже вивільнено вручну, тому викликати деструктор (`~ClassName()`) більше не потрібно. Це економить ресурси процесора.

6. Dispose(true) — ми робим прибирання вчасно самі. Тому можна безпечно очистити і пам'ять програми, і закрити відкриті файли чи бази даних.
   Dispose(false) — це страховка, якщо ми взагалі забули за собою прибрати. Збирач сміття вже сам викинув пам'ять програми, тому вам лишається тільки закрити файли, щоб вони не лишилися заблокованими в системі.
