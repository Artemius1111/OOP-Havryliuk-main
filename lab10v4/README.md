# Лабораторна робота №10: LINQ в дії: фільтри, join, агрегації. Продуктивність.

**Тема:** LINQ в дії: фільтри, join, агрегації. Продуктивність.

**Мета:** Навчитися ефективно використовувати LINQ для фільтрації, об'єднання (join) та агрегації даних, а також аналізувати продуктивність LINQ-запитів.


## Хід роботи

За допомогою .NET CLI створено консольний проєкт lab10v4 у директорії OOP-Havryliuk.

Створено класи сутностей Author (автор) і Book (книга) та заповнено тестові дані: 13 авторів і 22 книги.

Виконано чотири запити за варіантом 4: пошук книг Stephen King після 1990 року, об'єднання книг з авторами, підрахунок кількості книг кожного автора та пошук найстарішої книги. Кожен запит написано в синтаксисі запитів і в синтаксисі методів, для кожного виміряно час виконання за допомогою Stopwatch.

## Висновок

Обидва синтаксиси працюють однаково швидко. Перший запуск кожного запиту найдовший через JIT-компіляцію. Найдорожчими виявились запити з об'єднанням і сортуванням, найшвидшим — пошук найстарішої книги.

## Відповіді на контрольні питання

* **Різниця між синтаксисом запитів та синтаксисом методів?**
  Синтаксис запитів схожий на SQL і зручний для об'єднань та групування. Синтаксис методів потрібен для операцій, яких немає в синтаксисі запитів, наприклад Count чи First. Працюють вони однаково.

* **Для чого Join та GroupJoin? У чому відмінність?**
  Обидва об'єднують колекції за ключем. Join повертає лише пари, що збіглися, а GroupJoin для кожного елемента повертає групу відповідних елементів, навіть порожню.

* **Приклади агрегуючих операцій.**
  Count, Sum, Average, Min, Max, Aggregate — обчислюють одне значення з усієї колекції.

* **Як виміряти продуктивність LINQ-запитів? Що на неї впливає?**
  За допомогою Stopwatch, повторивши запит багато разів. Впливають розмір даних, сортування, об'єднання та повторне виконання відкладених запитів.
