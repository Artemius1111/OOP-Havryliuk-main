# Лабораторна робота №10: LINQ в дії: фільтри, join, агрегації. Продуктивність.

**Тема:** LINQ в дії: фільтри, join, агрегації. Продуктивність.

**Мета:** Навчитися ефективно використовувати LINQ для фільтрації, об'єднання (join) та агрегації даних, а також аналізувати продуктивність LINQ-запитів.

**Варіант 4:** Бібліотека.


## Хід роботи

У ході виконання роботи за допомогою .NET CLI було створено консольний проєкт `lab10v4` у директорії `OOP-Havryliuk` (команда `dotnet new console -o OOP-Havryliuk/lab10v4`).

Для представлення даних створено два класи сутностей:

* `Author` (властивості `Id`, `Name`, `Country`) — автор книги;
* `Book` (властивості `Id`, `Title`, `AuthorId`, `Year`) — книга. `AuthorId` посилається на `Author.Id`, тобто один автор може мати багато книг.

У статичному класі `LibraryData` створено тестові колекції: 13 авторів і 22 книги (роки видання від 1813 до 2019). У Stephen King 8 книг — частина до 1990 року, частина після, щоб перевірити фільтр за роком. В автора Andrzej Sapkowski навмисно немає жодної книги, щоб показати різницю між `Join` і `GroupJoin`.

Клас `Benchmark` вимірює час кожного запиту через `System.Diagnostics.Stopwatch`: спочатку один «перший запуск» (він включає JIT-компіляцію), потім 10 000 повторів, з яких рахується середній час одного запуску в мікросекундах. Кожен запит закінчується `ToList()` або `First()`, бо через відкладене виконання без цього Stopwatch виміряв би лише створення запиту, а не його виконання. Наприкінці програма виводить підсумкову таблицю часу, відсортовану від найповільнішого запиту.

Для кожного запиту програма також перевіряє, що синтаксис запитів і синтаксис методів повертають однаковий результат.

### Запит 1. Книги автора "Stephen King", видані після 1990 року

```csharp
from b in books
join a in authors on b.AuthorId equals a.Id
where a.Name == "Stephen King" && b.Year > 1990
orderby b.Year
select b
```

```csharp
books.Join(authors, b => b.AuthorId, a => a.Id, (b, a) => new { Book = b, Author = a })
     .Where(x => x.Author.Name == "Stephen King" && x.Book.Year > 1990)
     .OrderBy(x => x.Book.Year)
     .Select(x => x.Book)
```

Результат: The Green Mile (1996), Dreamcatcher (2001), 11/22/63 (2011), Doctor Sleep (2013), The Institute (2019).

### Запит 2. Книги разом з їхніми авторами

```csharp
from b in books
join a in authors on b.AuthorId equals a.Id
select new { b.Title, Author = a.Name }
```

```csharp
books.Join(authors, b => b.AuthorId, a => a.Id, (b, a) => new { b.Title, Author = a.Name })
```

Результат: 22 пари «назва книги — ім'я автора».

### Запит 3. Кількість книг для кожного автора

```csharp
from a in authors
join b in books on a.Id equals b.AuthorId into authorBooks
let count = authorBooks.Count()
orderby count descending, a.Name
select new { Author = a.Name, Count = count }
```

```csharp
authors.GroupJoin(books, a => a.Id, b => b.AuthorId,
                  (a, authorBooks) => new { Author = a.Name, Count = authorBooks.Count() })
       .OrderByDescending(x => x.Count)
       .ThenBy(x => x.Author)
```

Результат: Stephen King — 8; George Orwell, Haruki Murakami, J. R. R. Tolkien — по 2; ще 8 авторів — по 1; Andrzej Sapkowski — 0.

### Запит 4. Найстаріша книга

```csharp
(from b in books orderby b.Year select b).First()
```

```csharp
books.OrderBy(b => b.Year).First()
```

Результат: «Pride and Prejudice» (1813), автор Jane Austen.

## Висновки щодо продуктивності

* **Перший запуск завжди найповільніший.** Він включає JIT-компіляцію лямбд і методів LINQ, тому триває в десятки-сотні разів довше за середній час. Один замір Stopwatch не показує реальну швидкість — запит треба повторювати багато разів і брати середнє.
* **Синтаксис запитів і синтаксис методів однаково швидкі.** Компілятор перетворює `from ... where ... select` на ті самі виклики `Join`, `Where`, `Select`, тому різниця між Query і Method — у межах похибки.
* **Найдорожчі — запити з об'єднанням і сортуванням (запити 3 і 1).** `Join`/`GroupJoin` спочатку будує хеш-таблицю (`Lookup`) з другої колекції, а потім проходить першу; `OrderBy` додає сортування O(n log n). Запит 3 найважчий: він будує групи для всіх авторів, рахує `Count()` для кожної групи й сортує за двома ключами.
* **Join без сортування (запит 2) дешевший**, хоча повертає найбільше рядків: лише побудова хеш-таблиці та один прохід.
* **Пошук мінімуму (запит 4) — найдешевший.** `MinBy` робить один прохід по колекції (O(n)). `OrderBy().First()` у сучасному .NET теж оптимізований і не сортує всю колекцію, але має додаткові накладні витрати, тому для пошуку одного елемента краще `MinBy`.

## Відповіді на контрольні питання

* **Поясніть різницю між синтаксисом запитів та синтаксисом методів у LINQ. Коли який краще використовувати?**
  Синтаксис запитів (`from ... where ... select`) схожий на SQL, а синтаксис методів — це ланцюжок методів розширення (`Where(...).Select(...)`) з лямбда-виразами. Компілятор перетворює синтаксис запитів у виклики методів, тому результат і швидкість однакові. Синтаксис запитів зручніший для `join`, `group`, `let` і кількох `from`. Синтаксис методів потрібен для операцій, яких немає в синтаксисі запитів: `Count`, `First`, `MinBy`, `Take`, `Distinct` тощо.

* **Для чого використовуються операції `Join` та `GroupJoin`? У чому їхня відмінність?**
  Обидві об'єднують дві колекції за ключем, як `JOIN` у SQL. `Join` — внутрішнє об'єднання: повертає пари «книга — автор» і пропускає елементи без пари. `GroupJoin` для кожного елемента першої колекції повертає групу всіх відповідних елементів другої, навіть порожню. Тому в запиті 3 Andrzej Sapkowski має 0 книг, а зі звичайним `Join` його в результаті не було б зовсім.

* **Наведіть приклади агрегуючих операцій LINQ та поясніть їхнє призначення.**
  `Count()` — кількість елементів (кількість книг автора), `Sum()` — сума, `Average()` — середнє значення, `Min()`/`Max()` — мінімальне/максимальне значення (найменший рік), `MinBy()`/`MaxBy()` — елемент з мінімальним/максимальним ключем (найстаріша книга), `Aggregate()` — довільна накопичувальна операція. Усі вони виконуються негайно й повертають одне значення.

* **Як можна виміряти продуктивність LINQ-запитів? Які фактори впливають на неї?**
  Через `System.Diagnostics.Stopwatch`: `StartNew()` перед запитом, `Stop()` після, результат — у `Elapsed`. Запит треба матеріалізувати (`ToList()`, `Count()`), повторити багато разів і взяти середнє, а перший запуск враховувати окремо через JIT. Для точних замірів використовують бібліотеку BenchmarkDotNet. На швидкість впливають розмір колекцій, тип операцій (фільтр — O(n), сортування — O(n log n), join — з побудовою хеш-таблиці), порядок операцій (спочатку `Where`, потім `OrderBy`), повторне виконання відкладених запитів і виділення пам'яті під нові об'єкти.
